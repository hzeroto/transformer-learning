# 学习者画像与教学约定

> 本文件保存跨聊天长期有效的信息。新教学任务不能假设自己拥有历史聊天，必须先读取本文件。

## 学习目标

- 从基础概念开始彻底理解 Transformer，而不是只会调用现成接口。
- 最终能够在理解每一步的基础上，独立手写 Transformer 及常见变体，并能验证、排错和解释设计取舍。
- 职业方向是从后端工程师转向 AI Infra；掌握 Transformer 是整体准备的一部分。本仓库重点是模型原理、实现、训练与增量推理，并连接资源和性能分析。
- 保留原版 Transformer、GPT/BERT/T5、LLaMA 风格组件与组合、KV Cache、滑窗、FlashAttention、MoE 和 ViT 的原目标；先尽早完成 mini-GPT，再展开架构与推理分支。
- 学习强度可以很高，但完全按知识依赖与能力关卡推进，不按日期、天数、周次、课时或预计耗时安排，也不以时间判断掌握。

## 已知背景

- 理解普通矩阵乘法的基本逻辑。
- 能完成基础 LeetCode 题目。
- 有后端工程师经历和 Go 开发经验，可利用接口设计、状态管理、测试及性能分析经验，但不假定已熟悉机器学习工程。
- 四年前使用 C++ 参加过算法竞赛，具备编程和算法经验，但不应假设相关知识仍然熟练。
- 已通过基础 shape、索引、批量矩阵乘法、转置和广播的解释或实现验证；不要回到这些定义重教。尚需按实际任务补齐存储布局、训练工程及设备执行机制，具体状态以 progress.json 为准。
- 在本项目开始时，对 Encoder、Decoder、训练与推理、Q/K/V 的来源等概念没有完整背景。

## 教学偏好

- 使用中文，表达直接、具体。
- 机器学习与 Transformer 的实现练习默认使用 Python/PyTorch；Go/C++ 背景只用于必要的语法或概念类比，除非学习者明确要求，否则不使用 Go/C++ 作为练习语言。
- 严格遵守先修顺序；使用新术语前先定义，不要用另一个尚未学习的概念解释当前概念。
- 每次推进一个有完整数据流、可独立实现的知识块；先解释关键新机制，再给公式与代码，不把已会的单个运算符拆成独立课。
- 教学设计的核心交付是能帮助掌握目标知识块的实际讲解、例子、必要图解与少量有效检查，不是课程安排说明。全局路线、map 和当前能力用于备课；不设固定的“为什么学”章节，必要模块最多简短定位，不让学习动机或规划报告喧宾夺主。
- 教学设计、练习设计和审查验收可采用仓库 skill；课堂内的“继续推进”“没懂”等自然对话不需要每轮重新触发 skill。课案可随理解情况调整，不规定固定问答节奏。
- 相邻概念可以逐步讲解后在同一份综合作业中验收；知识地图的节点不是必须拆开的课时或作业。遇到前向、输出层等已有数学基础覆盖的桥接内容，优先在训练闭环中确认。
- 教师提供接口、约束与有区分力的测试，学习者填写核心实现；review时先检查和解释，未经要求不代写或修改学习者答案。
- 按需解释新 Python/PyTorch API；能查文档和语法提示。API 名称记错不等于概念未理解，不能以背 API 作为关卡。
- 解释 shape 时，要区分“轴的数量”“每个轴的长度”和现实空间中的三维，不把高阶张量说成几何立体。
- 说明“数据来自哪里”时必须指出具体对象和生成步骤，例如“哪个张量由哪一步计算得到”，不能只说“来自 Decoder”之类缺少主语和阶段的表述。
- 题目必须自包含：列清每个符号代表的对象、计算阶段、已知 shape 和轴顺序；区分 head 这一路计算、单头输出、合头前张量与合头后张量。若省略 B/T 等轴，必须明确固定了哪些索引，以及局部对象是向量还是矩阵；若 shape 本身是考点，应明确它待推导及足够的已知条件。不要依赖学习者记住数条消息前的临时命名，也不要把题面或记法不清造成的回答直接当成概念不懂、连续追加小题。
- 训练与推理只有在成为当前概念的必要前提时才引入；一旦两者行为不同，要明确区分。
- 不安排无助于理解的重复手算。可以用小数字举例，但如果学习者已经表示理解，就继续推进。
- 学习者明确反馈基础拆轴与小步确认过慢：默认按完整模块加速，紧邻机制在一次讲解后用同一份综合实现验收；已通过的 shape/布局操作不再单独出题。仍解释新语法与关键语义，不因加速推定未验证的能力已掌握；非阻塞的小缺口可在后续集成中核验。
- 避免把课程讲成互不关联的知识点：进入新模块时先交代它在完整模型、训练或生成数据流中的位置；跨过重要组件边界时做整体串联。全局复习优先沿同一个预测任务连接已有代码、参数、激活与梯度，再回到当前待完成关卡，不用重做低价值手算。
- 对明显低于学习者编程与推理能力的基础概念，只做一次高信息密度的边界验证；优先使用反例、代码实现、组合约束或排错题，避免连续询问直接复述定义即可回答的问题。
- 数学表达必须确保可读。优先使用简单 Markdown/LaTeX；若渲染可能出错，同时给出纯文本 shape 或索引表达。
- 讲解应图文配合：整体关系用清晰的数据流图，张量轴与索引用具体小样例的矩阵/网格图，机制差异用并排对照；图旁标明数据来源、shape 和必要解释。每张图聚焦一个关键关系，保持符号与颜色含义一致，避免拥挤、错位的字符连线图，也不为简单事实强行加图。优先先定位整体，再放大局部，最后对应到公式和代码。
- 通过简短解释题、shape 判断、代码实现或排错验证理解，不以“听过讲解”作为掌握证据。
- 学习者指出背景缺失或术语跳跃时，立即退回缺失的先修知识，而不是继续堆叠概念。
- 核心阶段可以使用 Tensor、autograd、参数注册和模块组织机制；线性层、归一化、Attention、FFN等核心数学自行实现，禁用 nn.Transformer、nn.MultiheadAttention 或融合注意力接口代做。先完成自写版本后，可把官方实现用于数值参照和后续性能对比。
- 在一份实现上逐步形成训练、验证、生成与基准能力，避免为每个架构复制整套工程；核心模型在CPU上缩小验证，GPU性能实测单独记录硬件条件。

## 已观察到的理解特点

- 能快速抓住矩阵乘法中最后两个维度的运算关系以及批次维的重复含义。
- 对模糊术语非常敏感；完整的数据来源、变量角色和计算阶段比类比更重要。
- 会主动质疑不完整的解释，适合通过精确定义和可验证例子建立理解。

## 掌握判定

- `learning/progress.json` 是知识点状态的真值来源。
- 只有出现可观察证据时才能标记为已掌握，例如独立解释、实现、测试或定位错误。
- 任何“已掌握”更新都必须调用 `npm run learning:report -- master ...`，不得直接修改生成文件。
