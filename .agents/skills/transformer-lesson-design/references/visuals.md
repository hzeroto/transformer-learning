# 教学图解

需要图解时读取本文件。图的任务是解释一个具体关系，不是装饰讲义。

## 选择表达方式

| 要解释的对象 | 合适的表达 |
|---|---|
| 多个组件的输入来源、分支与汇合 | 简洁数据流或结构图 |
| 轴、索引与拆合张量 | 有具体元素和轴标注的矩阵/网格 |
| 两种机制的计算或可见范围差异 | 共享符号、尺度和输入的并排对照 |
| 数值性质或尺度变化 | 由真实计算数据绘制的曲线/散点图 |

先确定要让学习者看懂的关系，再选择工具。精确的张量与结构图优先采用可编辑、可校验的 SVG、HTML 或程序绘图。
如果当前环境有适用的可视化 skill，读取并按其要求使用；不要假设某个插件一定可用。
无论采用何种绘制方式，都不能把图里的数字、箭头或公式当作已自动验证的事实。

## 制作与核对

- 一张图聚焦一个关系，轴顺序、变量名和颜色含义与讲义保持一致；颜色不能是唯一标识。
- 箭头说明谁流向谁；需要区分时标注是张量传递、逐元素运算还是矩阵乘法，不能让加法看起来像拼接。
- 张量旁注明完整 shape；如果图只显示一个 batch、token 或 head，说明固定的索引。
- 图旁提供简短文字解释；精确数值图用可运行计算核对，小型索引图逐项核对元素对应。
- 实际渲染后用可用的图像查看或浏览器工具检查：裁切、重叠、中文字体、箭头方向、公式和小屏可读性。
- 数学表达若无法可靠渲染，改用简单公式、纯文本索引或代码块。避免拥挤的字符连线图。
- 图解资产随讲义保存在 `notes/` 下的相关资源目录，并使用可解析的相对链接。临时生成路径不能充当持久材料。
- 不能只写“此处配图”。若环境确实无法生成或预览，提供准确的文字/表格替代，说明图解或视觉核验未完成，不假称已检查。
