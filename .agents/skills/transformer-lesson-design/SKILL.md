# Transformer 教学设计

根据学习者当前能力，设计一份能帮助其真正掌握目标知识块的教学内容。
交付实际讲解与材料，不只交付课程目录、备课提纲或流程报告。
用户当前明确要求优先于本 skill 的默认做法。

## 读取设计依据

- 先按项目入口完成操作系统、映射仓库根目录与 origin 的身份核验，再完整读取仓库 [AGENTS.md](../../../AGENTS.md)。不从 cwd 或 skill 安装目录猜项目路径；缺少项目入口时先确认仓库。
- 读取 `learning/learner-profile.md`、`learning/roadmap.md`，检查 `learning/map.json` 中相关节点、必要先修与验收标准，以及 `learning/progress.json` 中的实际能力证据。
- 按需读取相关讲义、练习接口与实现；只有状态证据不清时才追查对应的 `learning/records.jsonl`，不要重放全部学习历史。
- 以当前请求和最新能力状态为准，不采用旧讲义中的进度快照。`currentNodeId` 为空不代表从头开始。

## 设计并写出教学内容

1. 选定一个连贯的知识块，明确学习者学完后应能解释、实现或排查什么。可以覆盖多个节点，不按节点数量、日期或预计时长切课。
2. 区分已会、需要短暂唤回、必须补讲的内容。查看待验证项具体缺什么；不因一个非阻塞的小缺口重教整块，也不跳过本课真正依赖的新机制。
3. 直接展开关键概念与计算。组织顺序服务理解，不强制固定章节；不设“为什么学”环节，整体位置必要时用一句话交代。机制为何如此设计，可以在解释机制时讲清。
4. 定义对象、数据来源、轴语义，再沿一致的符号追踪形状与计算。区分完整张量和固定某些索引后的局部向量；简化假设及适用范围必须说清。
5. 用有代表性的例子或反例消除关键误解，按需解释首次出现的 Python/PyTorch 语法。代码片段在机制讲清后出现；保留学习者后续独立实现的空间，不给出其待交作业的完整答案。
6. 在关系确实难以用文字表达时，按 [图解要求](references/visuals.md) 制作并检查实际图解；简单事实不强行配图。
7. 只针对尚缺的关键证据准备少量理解检查或实现任务。题目自包含，不能考未讲内容；已有证据充分的部分不再重复手算或背 API。

## 交付与后续对话

- 默认把可复用讲义放在 `notes/`，先检查并复用同主题材料；随讲义保存所需图解资源。若用户只要聊天内内容或指定位置，遵从其要求。
- 正文面向学习者，核心是解释、例子、图解与代码。节点映射、先修判断和验收目标仅保留必要的简短交接信息，不让备课过程占据正文。
- 交接时明确哪些内容只是准备好了、哪些已经实际讲过。练习设计不能把“讲义已生成”当作“先修已掌握”。
- 课案允许自然对话中补充、跳过已会部分或调整例子，不要求逐段确认，也不规定每次“继续”“没懂”都重新执行本 skill。
- 编排教学不自动修改 `map.json` 的依赖、重排整个路线或更新能力状态。确有地图问题时指出依据与建议；仅准备材料不代表开始学习或掌握。

## 交付前核对

检查讲解是否实际完成、公式与样例是否一致、新术语是否先定义、图中文字是否可读、题目条件是否充分。
讲义描述已有工程能力时，区分真实完成的实现和组合草图。
不要声称设计了一份课就保证已经掌握；掌握取决于后续可观察表现。
