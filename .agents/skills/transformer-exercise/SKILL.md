# Transformer 练习设计

交付可运行、可检验的工程练习，让学习者独立完成目标计算。
用户当前明确要求优先于本 skill 的默认做法；请求答案或实现属于不同任务，不能继续伪称是独立练习。

## 确定练习边界

- 先按项目入口完成操作系统、映射仓库根目录与 origin 的身份核验，再完整读取仓库 [AGENTS.md](../../../AGENTS.md)。不从 cwd 或 skill 安装目录猜项目路径；缺少项目入口时先确认仓库。
- 读取 `learning/learner-profile.md`，检查 `learning/roadmap.md`、`learning/map.json` 与 `learning/progress.json` 中本任务的范围、依赖和证据。
- 读取相关讲义及实际接口；确认新机制已经讲过。只有讲义文件存在不足以证明已讲或已会；若确有必要先修未讲，先做针对性解释，再交付可实现的练习，不拿新概念出题让学习者猜。
- 检查工作区变更、同主题练习和测试。扩展已有练习时保留学习者答案；复用已验收组件，不为多个节点创建重复作业。
- 先定义一份完整可实现的任务，再选需要覆盖的节点。不要让通用参数校验或部署工程盖过本次学习目标。

## 交付接口、脚手架和测试

- 在 `exercises/` 的适当位置提供核心函数签名、完整 docstring 和明确的 `NotImplementedError`/TODO；在 `tests/exercises/` 提供测试。沿用当前仓库的命名与导入方式，不硬编码未来练习编号。
- 契约说明每个对象的含义、来源、shape、轴顺序、返回值、参数与请求状态、允许的 dtype/device、数值容差及本次要求的异常行为。
- 按任务声明 mask 真值含义、广播轴、PAD 语义、是否保留梯度、是否允许原地改动和非连续输入等相关边界；无关的项不机械加入。
- 题目条件必须自包含。若 shape 本身待推导，明确足够的已知条件；不为了写清契约直接泄露考点答案。
- 首次出现的必要 Python/PyTorch API 给简短说明。基础 Tensor/autograd 可用，核心数学不得由高级 Transformer、Attention 或融合接口代做；参考实现的使用范围遵循当前教学阶段。
- 辅助代码不能替学习者完成目标计算。示例应展示调用与输入输出语义，不把完整答案藏在 demo、模板、TODO 注释或直接调用的参照函数中。
- 测试设计和自检前读取 [测试与隔离自检](references/testing.md)，选择能识别本任务典型错误的测试。
- README 写清任务、运行命令、空脚手架预期的未实现失败/跳过、最终完成标准。更新练习索引，不把新脚手架标成已验收。

## 验证后交付

明确区分“空脚手架可以导入和发现测试”“教师参照通过测试”和“学习者完成实现”三种结果。
运行相关已有回归，确认没有破坏前置组件。只报告实际运行的命令、结果和未验证范围。
最终答复简洁指出待填写的文件/函数和运行命令，不再复制全部题面或给出答案。
创建作业不更新掌握状态，不擅自改知识地图、已有答案或训练环境依赖。
