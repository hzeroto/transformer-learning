# 测试与隔离自检

## 选择有区分力的测试

先列出本次接口可能出现的关键错误，再选能区分正确与错误实现的输入。
根据任务选用以下类别，不要求每份练习全部覆盖：

- **元素与语义**：输出 shape 正确但轴语义错误；用明确编号元素、不同轴长和独立索引参照检查。
- **独立参照**：避免测试和待测代码共享同一个有风险的 helper 或广播路径。拆头/合头不能只测往返，两个错误可能互相抵消。
- **性质和边界**：例如 Attention 的未来/PAD 扰动、全屏蔽行、不同 Q/K 长度；归一化的常量输入、轴选择和 epsilon。仅测契约要求的行为。
- **梯度**：前向正确不代表计算图完整；检查要求求导的输入/参数，必要时做有限差分或独立梯度对齐。参照依赖官方实现时，先确认当前阶段允许。
- **布局与广播**：适用时覆盖连续、转置、步长切片；不同轴长和偶然相等的轴长都可能重要，例如 `B == H` 的错误 mask 广播可以静默运行。
- **状态与迭代**：训练清梯度、参数更新、缓存追加/重置和请求隔离需要多步测试，单次输出或 loss 下降不足以证明。

声明随机种子、设备、dtype、容差和计时范围（若涉及性能）。
测试精确索引可要求相等；不同浮点计算路径通常需要合理容差，不能复制别题的容差而不检查。
失败信息要能定位到对象或行为；不限定唯一写法，不用匹配源码字符串来替代数学正确性。

## 自检而不代写

1. 检查新模块能导入、测试可发现、README 的命令确实指向该练习。未实现失败应明确，不能因所有测试跳过就显示完成。
   空框架会产生大量重复报错时，可采用一个明确的实现状态失败、其余行为测试暂跳过的模式；说明这是未完成状态，最终验收仍要求行为测试实际运行通过、无跳过。
2. 在新建的临时目录或内存中，用独立教师实现验证新测试和数据的正确性；不要将答案暂时写入学习者文件再恢复。
3. 若测试本身含可读的数学参照，明确它属于教师测试；这不是独立测试设计或闭卷证据。可查基础 API 的日常练习与不给模型答案的闭卷任务分开处理。
4. 对高风险机制，隔离注入少量真实的典型错误，确认测试确实会失败。不要为凑变异数量制造不可能发生的错误。
5. 跑相关已有测试；加入空脚手架后，全仓可能出现预期的未实现失败或跳过，分别说明，不能把这种状态宣称为全仓全绿。
6. 检查最终 diff：目标核心函数仍待学习者实现、已有答案未改变、临时参照未落入作业、无无关文件。

在真实仓库根目录，当前 Python 全仓入口是：

```bash
.venv/bin/python -B -m unittest discover -s tests -t .
```

`-t .` 固定顶层包路径，避免 `tests/exercises` 和 `exercises` 名称冲突。
指定测试模块的命令需按本次实际文件生成，不写死旧练习或旧测试数量。
运行环境缺失时先检查已有解释器和依赖说明；未经请求不改依赖或安装硬件后端。
