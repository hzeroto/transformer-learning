## Q、K、V 的具体来源

当前讨论同一序列内部的读取。输入 X 的 shape 是 (B,T,C)，可由已有
内容查表与位置表示生成：X[b,t,:] = E[input_ids[b,t]] + P[t]。

“投影”在这里指用参数矩阵做线性变换，不要求是几何中的正交投影。

- Q（Query，查询）：每个位置用于提出匹配请求的向量，Q = X @ Wq。
- K（Key，键）：每个候选位置提供的匹配依据，K = X @ Wk。
- V（Value，值）：每个候选位置提供的待读取内容，V = X @ Wv。

Wq、Wk、Wv 是三份独立的可训练参数，跨输入保留；
Q、K、V 是本次 X 与对应参数计算出来的结果。
这些名称描述计算用途，并不意味着某个分量有预先规定的自然语言含义。

| 对象 | shape |
|---|---|
| X | (B,T,C) |
| Wq、Wk | 各为 (C,Dk) |
| Wv | (C,Dv) |
| Q、K | 各为 (B,T,Dk) |
| V | (B,T,Dv) |

Dk 是匹配向量的分量数，Dv 是待读取向量的分量数。
Q 与 K 的最后一轴必须等长才能做点积；V 的最后一轴不必等于它们。
这三次变换分别作用于每个位置，此时还没有混合其他位置的内容。

## 两两原始分数

对于同一 batch，位置 i 用自己的 Q 向量，分别与每个位置 j 的 K 向量做点积：

scores[b,i,j] = sum_r Q[b,i,r] * K[b,j,r]

行 i 表示发起查询的位置；列 j 表示候选被读取位置。
在当前同序列场景中，scores 的 shape 是 (B,T,T)。
Q 与 K 使用不同的参数矩阵，因此 scores 不必对称。

一次算出所有配对可用 Q @ K.transpose(-2, -1)。
transpose(-2, -1) 交换最后两个轴，保留 batch 轴；
这里复用已掌握的转置与批量矩阵乘法。

raw_attention_scores 是一个只接收给定 Q、K 的计算函数，
因此接口也允许查询数量 Tq 与候选数量 Tk 不同，输出 (B,Tq,Tk)。
此处仅验证数量和索引语义，跨序列的数据来源留到对应学习点。

V 不参与这个分数公式。之后再讲如何把分数转换为比例并读取 V。
现在得到的仍是原始分数，不代表已完成 Attention，也不能直接作为因果模型使用。

## 第二部分：均值、方差与 Attention 分数尺度

本节解释为什么把原始点积除以 `sqrt(Dk)`，不提前引入完整概率论。
Q/K 的来源与两两分数已经通过，直接复用已有 `raw_attention_scores`。

### 先分清向量数据与维度数

q、k 是各含 Dk 个数的向量；Dk 自身是一个正整数，不是数组。
对于一维 q，用 Go 类比，Dk 对应 `len(q)`，而不是 q 本身。
若 Q 的 shape 为 `(2,3,64)`，则 `Q.shape[-1]` 得到整数 64，
`sqrt(Dk)` 就是 `sqrt(64)=8`。它不读取 q/k 的数值来求实际标准差。

```python
import math  # Python 自带的数学模块。

d_k = Q.shape[-1]                             # Python int，例如 64。
scores = raw_attention_scores(Q, K)           # (B,Tq,Tk)
scaled_scores = scores / math.sqrt(d_k)       # 每个分数都除以同一个数 8。
```

只要最后一轴长度不变，无论 Q/K 的具体数据怎样变化，这个分母都不变。
“分数的理论标准差在简化假设下等于 sqrt(Dk)”是选择这个分母的统计理由；
“从本次向量数据中计算标准差再除以它”是另一种实际操作，二者不能混为一谈。

### 一组数的中心与波动

对给定的 n 个数，本节定义：

```text
均值     = 这些数的和 / n
方差     = 每个数减均值后，偏差平方的平均
标准差   = 方差的平方根
```

均值描述中心，标准差描述围绕中心的波动尺度。比如 `[-1,1]` 的均值为 0、方差为 1、
标准差为 1；`[-8,8]` 的均值仍是 0，但方差为 64、标准差为 8。
偏差需要平方，否则正负偏差直接平均会抵消。

对 `x: (B,T,Dk)`，按每个 token 的特征轴统计可以写成：

```python
mu = x.mean(dim=-1, keepdim=True)                # (B,T,1)
variance = ((x - mu) ** 2).mean(dim=-1, keepdim=True)
std = variance.sqrt()                           # (B,T,1)
```

`** 2` 是 Python 的乘方，不能用 Go/C++ 的按位异或符号 `^` 代替；
Tensor 的 `.sqrt()` 是逐元素开平方。`keepdim=True` 让均值能广播回对应 token 的特征。
这里按本节定义除以元素个数 n，不涉及统计估计时的分母修正。
这些代码只是定义统计量，Attention 缩放本身不需要先计算 Q 每行的均值或方差。

### 平移、缩放和相加

设 a、b 是固定常数：

```text
均值(a*x+b)   = a*均值(x)+b
方差(a*x+b)   = a²*方差(x)
标准差(a*x+b) = |a|*标准差(x)
```

平移同时移动数值与均值，不改变偏差；乘 a 会把偏差乘 a、偏差平方乘 a²。
因此，要把方差缩小 Dk 倍，应把数值除以 `sqrt(Dk)`，不是除以 Dk。

下面讨论随输入或随机初始化而取不同值的量，称为随机变量；
均值和方差此时是按各取值的概率求平均，采集一批数再平均是对它们的估计。
这不意味着每次前向还要额外抽随机数。

两个量独立，指知道其中一个的取值不会改变另一个的取值概率。
独立能保证其方差相加；更弱的“不相关”也足够，含义是去均值后两者乘积的平均为 0。
不能无条件把方差相加：若每次都有 `b=a`，则 `a+b=2*a`，
当 a 方差为 1 时，这个和的方差为 4，不是 2。

### 点积为什么随 Dk 增长

固定一个查询和一个候选，其分数是：

```text
score = q[0]*k[0] + ... + q[Dk-1]*k[Dk-1]
```

采用一个用于分析尺度的简化模型：所有 q/k 分量彼此独立、均值为 0、方差为 1。

这里的独立对象必须展开说明。`q=Q[b,i,:]`、`k=K[b,j,:]` 是选定的一对向量，
各有 Dk 个分量。本段采用的是这 **2*Dk 个标量全部相互独立** 的较强假设，包含：

- q 内部各分量相互独立。
- k 内部各分量相互独立。
- 整个 q 向量与整个 k 向量独立，也包括不同维度之间的 q/k 配对。

独立描述重复取样时的概率关系，不是一次已经计算出的数值必须不同，
也不是说张量内存分开、向量正交或参数矩阵不同。一次前向算出的 Q/K 是确定的；
本段分析的是不同样本或初始化下这些量可能的取值。
一个满足该假设的人工构造是：独立抛 2*Dk 次公平硬币，每次按正反面取 +1/-1，
前 Dk 次组成 q，后 Dk 次组成 k。独立抽取的分量也可以偶然取到相同数值。

只要求 q 与 k 两个向量独立是不够的。例如分别独立抽取 a、c，再令：

```text
q = [a,a]
k = [c,c]
score = a*c + a*c
```

q 和 k 两组彼此独立，但各自内部复用了同一个数，两个乘积项完全相同，
因此不能把它们当成两份独立波动来相加。

后面的证明分两步阅读：先利用同一乘积内 q[r] 与 k[r] 独立，分析单项乘积；
再利用不同乘积项独立（方差相加只需不相关），分析它们的和。
实际 Q=X@Wq、K=X@Wk 共享输入来源，不能仅从投影参数不同推出统计独立。
下面是尺度分析的简化模型，不是对真实 Q/K 的无条件断言。

先明确两种不同的平均：

- 样本均值：对实际采到的有限个数做算术平均。
- 期望：把所有可能结果按其出现概率加权，得到分布的理论平均。

即使样本来自独立的 a、b，也不能对任意两条已观察样本断言
`(a1*b1+a2*b2)/2 = ((a1+a2)/2)*((b1+b2)/2)`。
例如观察到 `(a1,b1)=(1,1)`、`(a2,b2)=(-1,-1)`，左边为 1，右边为 0。
这是有限样本的算术关系，不因抽样来源独立就自动成立。

独立保证的分解作用于期望。例如 a、b 各以 1/2 概率取 +1/-1，且相互独立，
那么四个可能组合 `(1,1)`、`(1,-1)`、`(-1,1)`、`(-1,-1)` 各有 1/4 概率。
乘积的期望是 `(1-1-1+1)/4=0`，等于两者期望的乘积 `0*0`。
独立使每个组合的概率等于各自取值概率的乘积，这是可分解的原因。
若改为 b 总是等于 a，则只剩两个同号组合各 1/2，乘积期望为 1，不能再分解。
注意：独立抽取的有限样本也可能碰巧只观察到两个同号组合；
这和规定整个分布只有两个同号组合不是一回事。
不要为了让有限样本等式成立，人为给已有观测拼接不存在的交叉样本。

再只看同一维的一对分量，记 `a=q[r]`、`b=k[r]`、`z=a*b`。
下面都讨论分布的期望和方差，不是某一次 q 向量内的样本均值或样本方差。
假设 a、b 独立，期望均为 0、方差均为 1。
由方差定义，零期望意味着：`a² 的期望 = 方差(a) = 1`，b 同理。
独立时乘积的期望可分解；各自平方不会引入两者之间的依赖，因此也能用于 a² 与 b²：

```text
z 的期望 = a的期望 * b的期望 = 0
z² 的期望 = a²的期望 * b²的期望 = 1
方差(z) = (z - 0)²的期望 = 1
```

这一步只使用同一乘积内 a 与 b 的独立。接着才使用不同维度之间的独立：
它保证不同 `z[r]` 是独立项，因而下面可以将它们的方差相加。

把“方差可以相加”展开一次，避免当作需要背诵的新规则。
先看两个乘积项 z0、z1，它们的期望均为 0、方差均为 1，且独立。
期望对加法总能拆开，不要求独立；乘积期望的分解在这里才用到独立：

```text
s = z0 + z1
期望(s) = 期望(z0) + 期望(z1) = 0

方差(s) = 期望((z0+z1)²)
        = 期望(z0²) + 2*期望(z0*z1) + 期望(z1²)
        = 1 + 2*0 + 1
        = 2
```

中间交叉项为 0，是因为 `期望(z0*z1)=期望(z0)*期望(z1)=0`。
若 z1 实际是 z0 的副本，这个交叉项就不是 0，不能照搬结论。
对于期望不为 0 的量，应先减去各自期望再展开；独立保证交叉项期望为 0，
而只要求该交叉项期望为 0 就是不相关条件。

推广到 Dk 项：所有不同项之间的交叉项期望都为 0，只剩 Dk 个平方项，
每个平方项期望为 1。Dk 是项数这个整数，不是数组或本次数据的样本方差。

```text
方差(score)              = Dk
标准差(score)            = sqrt(Dk)
方差(score / sqrt(Dk))   = Dk / Dk = 1
```

最后一行使用了常数缩放的平方关系：分数除以 c，偏差也除以 c，方差除以 c²。
例如 Dk=64，分数的理论方差是 64、标准差是 8；除以 8 才把理论方差变为 1。
除以 64 则得到理论方差 1/64。这些是分布统计结论，不是对某个已算出的标量再求方差。

这说的是分数在重复样本中的波动，不是断言每个具体分数等于 `sqrt(Dk)`，也不是说
固定一个查询所对应的那一行分数，其样本方差必然恰好是 Dk。
真实 Q/K 来自可训练投影，独立、零均值、单位方差不保证严格成立；
除以 `sqrt(Dk)` 的作用是控制点积随特征数增长的典型尺度，不是强制实际方差精确等于 1。

Dk 是相乘再求和的特征数量，不是查询数 Tq、候选数 Tk，也不是 V 的内容维度 Dv。
原始分数 `(B,Tq,Tk)` 除以一个标量后 shape 不变。

### 这与稳定 Softmax 的减最大值不同

同一行分数减去最大值，数学上不改变 Softmax 概率；
除以正数则会改变分数差距，通常会改变概率分布，但不会改变最高分候选的排序。
例如 `[0,8]` 的第二候选概率约为 0.9997；除以 8 后变为 `[0,1]`，概率约为 0.7311。
减最大值不会使原来过于集中的分布变平缓。

分数差距很大时，Softmax 权重接近 0 或 1，对分数的小变化可能不敏感，
影响通过注意力权重回传的梯度。这里讨论的是该计算路径的敏感度，
不是说所有损失的梯度都会消失；不要和此前稳定交叉熵的性质混淆。

### 推导后的结构检查：复制维度是否保持分数

从末轴为 Dk=64 的 Q/K 出发，把各自已有的特征原样复制并拼接：

```python
Q2 = torch.cat((Q, Q), dim=-1)  # (B,Tq,128)
K2 = torch.cat((K, K), dim=-1)  # (B,Tk,128)
```

`torch.cat` 的 dim=-1 表示沿特征轴拼接，没有新增独立采样的特征。
分别用各自末轴长度的平方根缩放点积：旧版本除 sqrt(64)，新版本除 sqrt(128)。
请说明新的缩放分数是旧分数的多少倍，并指出为什么不能把复制出来的乘积项
当作独立项再推导方差。不要求手算矩阵或新增实现。

这一检查的结论：复制后原始点积变为 2 倍，除数变为 sqrt(2) 倍，
所以新缩放分数是旧分数的 sqrt(2) 倍。复制项与原项完全相同，不是独立的新项。
上述倍数关系是对每次具体计算都成立的代数恒等式，不依赖分布假设；
而此前方差随维度的推导需要相应统计假设。理论期望与有限样本统计量需要区分，
不是说采样不属于概率分析，也不是说实际 Q/K 必须满足理想假设。

### 每一行是在候选位置之间分配读取比例

沿用已实现的投影与原始分数，形状关系为：

```text
Q:       (B,Tq,Dk)
K:       (B,Tk,Dk)
V:       (B,Tk,Dv)
scores:  (B,Tq,Tk)  = Q @ K.transpose(-2,-1) / sqrt(Dk)
weights: (B,Tq,Tk)  = 对 scores 的每一行做 Softmax
```

同序列投影时 Tq=Tk=T；接口仍允许两种长度不同。
K 和 V 的 Tk 必须对应同一组候选，而且 K[b,j,:] 与 V[b,j,:] 必须属于同一个候选。
它们的特征数 Dk 和 Dv 可以不同：K 用于匹配，V 是要读出的内容。

`scores[b,i,:]` 固定 batch b 和 query i，比较所有 j 位置的候选。
`weights[b,i,j]` 是该 query 分给候选 j 的读取权重。
对有限分数，每行权重非负、和为 1：

```python
weights = torch.softmax(scores, dim=-1)
```

`dim=-1` 指末轴 Tk，不能按 query 轴 Tq 归一化，否则得到的就不是
“同一 query 在候选之间分配比例”。这是输入候选位置上的分布，
不是之前 `(B,T,N)` 对词表 N 个 token 的预测分布。
这里也不使用 argmax 或采样，所有候选按各自权重参与计算。

### 一个候选的整条 V 向量乘同一个权重

```text
output[b,i,:] = weights[b,i,0] * V[b,0,:]
              + weights[b,i,1] * V[b,1,:]
              + ...

output = weights @ V
(B,Tq,Tk) @ (B,Tk,Dv) -> (B,Tq,Dv)
```

消去的是候选轴 Tk，保留的是 query 轴 Tq；每个 query 得到一条长度为 Dv 的向量。
每个候选的权重作用于该候选的全部 Dv 个内容分量，而不是某个特征单独挑一个候选。

例如省略 batch 轴，下列是已算出的权重和配对的 V：

```text
weights = [[0.1, 0.7, 0.2],
           [0.6, 0.1, 0.3]]     # (Tq=2,Tk=3)

V = [[10,  0],
     [ 0, 20],
     [10, 10]]                 # (Tk=3,Dv=2)

output = [[3,16],
          [9, 5]]              # (Tq=2,Dv=2)
```

第一条输出就是 `0.1*[10,0] + 0.7*[0,20] + 0.2*[10,10]`。
这不是“挑出第二个 token”，而是把候选的内容向量按比例混合。
输出是新的特征表示，尚不是词表 logits，也不是下一 token 的编号。

### 为什么这一步终于能读取上下文

原来的逐位置模型在最后一个位置只计算 `(E[X]+P[2]) @ W`。
对于 `[BOS,A,X]` 和 `[BOS,B,X]`，最后的 token 和位置相同，因此该输出相同。
在同样的逐位置输入表示下，最后位置的 Q 仍相同，但前面 A/B 对应的 K、V 可以不同：
K 改变可能改变读取比例，V 改变可能改变混合的内容，因此最后输出可以不同。
这是模型具备利用前文的计算路径，不保证任意参数都会使两个输出不同或自动学会任务。

### 一个配对性质检查

固定 Q，不加 mask，只考虑给定 Q/K/V 到 output 的计算：

- 操作 A：交换 K 的候选第 0、2 行，V 不动。
- 操作 B：K 和 V 都交换候选第 0、2 行，保持原来的配对。

哪一种操作能保证 output 在数学上不变？另一种为什么没有这个保证？
用一个 query 的加权读取解释即可，不要求手算矩阵。
将来若有 mask 或其他按候选排列的量，也必须单独检查它们的对应关系，不能直接套用此题。

配对检查的结论：固定一个 query，原权重为 w0、w1、w2。
K 的第 0、2 行交换后，权重按相同顺序变为 w2、w1、w0。
若 V 也交换，输出为 `w2*V2 + w1*V1 + w0*V0`，仅求和顺序改变；
若只交换 K，则变为 `w2*V0 + w1*V1 + w0*V2`，一般不同。
数学不变不要求不同浮点求和顺序逐位相等，后续测试应使用明确容差。

这里是权重乘以 V 向量再求和，不是把权重本身加到 V，也没有自动加回 query 的原始特征：

```text
当前 Attention 输出：output = weights @ V
并没有额外执行：     X + output
```

同序列 Attention 允许读取自身时，自身的 V 也只是其中一个带权重的候选。
在维度匹配后另加原输入属于后续要讲的残差连接，不是本节加权读取的一部分。

## 第四部分：mask 是候选读取权限

已经理解的训练动机不再重复设问：target_valid 只决定哪些标签计入损失，
不能阻止输入中的未来答案被读取。本节把可见性落实到 scores 和 Softmax。

### True 表示允许 query 读取 key

先约定显式布尔张量 `allowed` 的 shape 为 `(B,Tq,Tk)`：

```text
allowed[b,i,j] = True  表示 query i 可以读取候选 j
allowed[b,i,j] = False 表示禁止读取
```

这里固定 True=允许；不同接口的布尔约定可能不同，不能只凭变量名猜测。
在当前同序列、Q/K 位置对齐且 Tq=Tk=T 的情形，因果规则是 j<=i：
可以读取自身和更早位置，不能读取未来位置。T=3 时：

```text
[[True, False, False],
 [True, True,  False],
 [True, True,  True ]]
```

每行对应一个 query，每列对应一个候选 key。
允许读取自身不等于泄漏答案：第 i 个输入位置要预测的是第 i+1 个 token。
不把 j<=i 不加说明地推广到 Q/K 位置不对齐的情况。

### 在 Softmax 前排除候选

以下 scores 已经除以 sqrt(Dk)，并假设每行至少有一个允许位置、未屏蔽分数有限：

```python
masked_scores = scores.masked_fill(~allowed, float("-inf"))
weights = torch.softmax(masked_scores, dim=-1)
output = weights @ V
```

- 对 bool Tensor，`~allowed` 是逐元素取反，True 与 False 互换；不是 Python 的整体 `not`。
- `masked_fill(condition, value)` 返回新张量，把 condition 为 True 的元素替换成 value，
  这里没有修改原 scores。
- `float("-inf")` 表示负无穷；对应指数为 0，因此该候选不贡献归一化分母，权重也为 0。

分数 `[0,0,0]` 禁止第三个位置时：

```text
先屏蔽： [0,0,-inf] -> Softmax -> [1/2,1/2,0]
后清零： [0,0,0]    -> Softmax -> [1/3,1/3,1/3] -> [1/3,1/3,0]
```

后一种没有重新归一化，禁止位置仍通过原 Softmax 分母影响可读位置的权重。
固定 Q 和允许候选的 K/V，只改变被禁止 K 的匹配分数，正确实现的输出应不变；
仅 Softmax 后清零的错误实现通常会变化。只检查禁止权重等于零不足以验证信息隔离。
在精确运算及允许概率和非零时，后清零再重新归一化可以数学等价，
但有限精度下允许概率可能已下溢为零；本阶段直接使用 Softmax 前屏蔽。

### 因果权限、PAD 与损失是不同约束

若输入有效性标记为 `input_valid: (B,T)`，同序列的组合规则为：

```text
allowed[b,i,j] = (j<=i) 且 input_valid[b,j]
```

input_valid 是 input_ids 的有效性，不是错开一位的 target_valid。
沿用训练数据切分时，分别是 `valid[:,:-1]` 和 `valid[:,1:]`。

- key 有效性：候选 j 是否真实，决定哪些列可被读取。
- query 有效性：查询 i 是否真实，决定该行输出是否有实际用途；不自动使输出为零。
- target_valid：该 query 对应的预测目标是否计入损失，既不等于 key 权限，也不替代因果规则。

这三个角色即使 shape 一样也不可混用。本阶段不把无效 query 行自动全部屏蔽，
其计算结果可存在但不用于有效监督；后续作为候选时仍需正确的 key 有效性标记。

### 全屏蔽行的基础接口约定

若某行没有任何允许候选，填充后就是全负无穷。指数归一化相当于 0/0，
常规稳定 Softmax 也会遇到负无穷减负无穷，结果为 NaN，而不是自动得到全零。
本阶段选择简单而明确的约定：Attention 接口要求每行至少有一个允许 key；
否则在 Softmax 前抛出 ValueError。将来支持全屏蔽行返回零时，必须另行约定前向和梯度。

当前包含有效起始位置的非空、右侧补齐批次可以满足这个约定。
下面的综合作业覆盖前屏蔽、候选配对、归一化轴、未来/PAD 扰动、全屏蔽行拒绝及梯度，
不再为每个步骤另做口头复述。

## 第五部分：综合实现（已验收）

### 只填写三个新接口

在 `attention.py` 中按顺序完成三个 `NotImplementedError` 占位：

| 接口 | 输入 | 输出与职责 |
|---|---|---|
| `make_causal_allowed` | `input_valid: (B,T)` | `(B,T,T)` 的因果与 key 有效性组合权限 |
| `scaled_dot_product_attention` | Q/K/V 与可选的 `allowed` | `(output,weights)`，完成缩放、前屏蔽、归一化及读取 |
| `single_head_self_attention` | X、三份投影参数、input_valid | 组合已有函数，完成因果单头自注意力 |

`self_attention` 的 self 表示 Q/K/V 都由同一份 X 生成，不代表只能读取自身。
第一个函数只构造权限，即使出现全 False 行也照常返回；第二个函数负责拒绝这种行。
第二个函数的 allowed 为 None 时允许所有候选，不隐式添加因果 mask；
第三个函数才负责构造并传入因果权限。这一层次区分应在代码中保持清楚。

详细 shape、dtype、返回顺序和错误约定见文档字符串。返回 output 在前、weights 在后。
不添加残差、Wo、位置编码、词表输出层或训练循环；这些不属于本次接口。
不要把目标标签有效性 target_valid 传成 input_valid。

### 本次可能用到的 Python/PyTorch 语法

`torch.arange(T)` 生成整数位置编号 0 到 T-1，例如 `torch.arange(3)` 得到 `[0,1,2]`。
这里调用 `unsqueeze` 只插入长度为 1 的轴，不复制一套新位置含义：

```text
positions:               (T,)
positions.unsqueeze(1):   (T,1)   每一行放该 query 的位置 i
positions.unsqueeze(0):   (1,T)   每一列放该 key 的位置 j
```

比较这两者时，已有的广播规则让结果成为 `(T,T)`，每个元素比较对应的 i 与 j。
结合 `input_valid: (B,T)` 时，它的 T 是候选轴，需要对齐到 `(B,1,T)`，
不是 `(B,T,1)`；后者会把有效性错用在 query 行上。
两份 bool Tensor 用 `&` 做逐元素“且”，不要用 Python 的 `and`；
比较表达式与 `&` 组合时，将各个比较表达式用括号包起来，避免优先级误解。

- `flags.any(dim=-1)`：每行只要有一个 True 就返回 True，shape 从 `(B,Tq,Tk)` 变成 `(B,Tq)`。
- `flags.all()`：只有所有元素都为 True 才返回 True，结果是标量 bool Tensor。
- 标量 bool Tensor 的 `.item()` 可取出 Python bool，供 `if` 做输入检查；
  这里只读不参与求导的权限标记，不要对 Q/K/V、weights 或 output 用它切断计算图。
- `raise ValueError("说明")`：报告不满足接口约定的输入。占位的 `NotImplementedError` 则表示尚未实现。
- 参数标注 `torch.Tensor | None` 表示接受 Tensor 或 None，`= None` 表示默认不提供 mask。

`math` 已导入，可使用 `math.sqrt`。允许直接用 `torch.softmax`，不要求重写之前的 Softmax 作业。
如果复用自己的 Softmax，仍必须正确支持至少一个有限数、其余可为负无穷的行。
